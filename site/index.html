AI arrives quietly: an app you tried once, a helper that starts at login, a new tool an assistant was handed last week, a plugin that runs commands on its own. Each one can read files, run commands or listen on a port.

Sooner or later a client, an insurer or an auditor asks which AI you use and what it can reach. A straight answer starts with a list. OptiCensus keeps it, with your decision and your reason beside every entry, ready to export as a spreadsheet.

What it finds

It looks in eleven places where AI lives on a Mac. A scan takes about a second and needs no special permissions.

Installed apps

AI apps in your Applications folders, with their version.

Running now

Assistants and model servers running at the moment of the scan.

Things that start by themselves

Launch agents, daemons and crontab lines that start an AI tool, and when they run.

Tools given to assistants

MCP servers set up for Claude Code, Claude desktop, Cursor, VS Code, Windsurf, Gemini and Codex, including those that arrive inside a plugin.

Listening ports

Local model servers, and whether they answer only this Mac or anyone on the network.

Command-line assistants

Assistants installed where your terminal can find them.

Names of AI keys

Which AI keys your shell start-up files set. The name only, never the key.

Browser extensions

AI extensions in Chrome, Edge, Brave, Arc, Vivaldi, Chromium and Opera.

Assistant plugins

Claude Code plugins, whether they are switched on, and what each brings: MCP servers, language servers, hooks and skills.

What runs without asking

What an assistant may do without asking you: Claude Code's permission rules and modes, Codex's approval policy, Gemini's auto-accept.

Hooks

Commands Claude Code runs by itself when an assistant starts, stops or uses a tool, from settings and plugins.

What it reports after each scan

  • NewSomething it has never seen before. It waits for your decision.
  • ChangedAn entry you allowed now does something different: an assistant was given another tool, or a start-up job runs an edited script. Your allowance no longer covers it, so it asks again.
  • ExposedA model server is listening beyond this Mac.
  • BackSomething you refused is present again.
  • GoneSomething you allowed has not been seen for 30 days.
  • UpdatedAn ordinary version update. It is noted, and your allowance stands.

Private by design

It reads names, not contents, and everything it finds stays in one folder on your Mac. If you link WorkFlow, the items that need you also go there as tasks, synced through your own iCloud.

It keeps

  • Names, paths and versions.
  • A short hash of a command's arguments, a start-up script, a permission rule, a hook or an extension's permissions, so a change is noticed without the content being stored.
  • Your decisions, who made them and why.

It never keeps

  • The value of a key or token.
  • Prompts or conversations.
  • The contents of your files.
  • Full command lines, or web addresses beyond the host name.
  • Anything in Desktop, Documents, Downloads or iCloud, unless you ask.

It cannot do

  • See what someone types into a chatbot in a browser.
  • Block or remove anything. It reports and keeps track.
  • Read Safari or code-editor extensions, or network traffic.
  • Allow something on your behalf. Every decision is yours.

WorkFlow is its console

Link OptiCensus to WorkFlow, our task manager for Mac, iPhone and iPad, and every entry that needs you becomes a task in an OptiCensus project.

Answer it wherever you are. Reply allow or deny, with a reason if you like, and the next scan records your decision, says so on the task and closes it. If something you allowed changes, a new task asks again. If a model server opens up to the network, its task is marked high priority.

One command links them: opticensus workflow connect. It uses WorkFlow's Agent Bridge, so there is nothing else to install.

Install it free

Version 0.1 for macOS 13 or later, Intel and Apple silicon. Free and open source under the MIT licence.

# install
npm install -g opticensus

# look, then decide
opticensus scan
opticensus show
opticensus allow claude --reason "used for client work"

# decide from WorkFlow instead, and scan every hour
opticensus workflow connect
opticensus schedule install

# the list for a client or an auditor
opticensus export --csv -o ai-register.csv

The npm package is the compiled tool and nothing else: no install script, nothing fetched at install time. Run opticensus reads for the full list of what it reads. The hourly scan is removed with opticensus schedule uninstall.
